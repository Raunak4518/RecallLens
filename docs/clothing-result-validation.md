# Clothing publication and resumable verification

PL064 and PL070 now validate the source evidence used by clothing results immediately before returning them. PhotoEvidenceValidation takes one final gallery revision snapshot for relevant gallery records, checks cancellation, validates only relevant non-gallery or unknown revisions individually, and rejects gallery records if broad access is denied or changes during validation. ClothingSearch filters both matching and related estimates, validates nearby anchors, preserves location-permission/missing-coordinate errors and supports confirmed unversioned sources through their consistent Named reference revision. No query opens a detector or garment model.

CachedGarmentAnalysis records the revision of each returned photo and validates the whole summary after the last progress callback. An earlier photo changed during later work is removed from evidence and its cached/processed count becomes unavailable. This prevents stale summary evidence even when the per-photo cache access was valid when it occurred. Stale encrypted rows follow normal source reconciliation; a result subset is never passed into a full-scope purge.

The new search tests use real SQLCipher evidence and an injected source snapshot to exercise edits, deletion, revoked access, unconfirmed lookalikes, related estimates, nearby-anchor loss and unversioned references. The summary test uses two generated MediaStore photos and changes the first from the final progress callback. This measures lifecycle correctness rather than real garment-model quality.

The core verifier now runs each selected class through a fresh instrumentation connection. It streams class transcripts and writes atomic successful class receipts. Explicit --resume reuse requires matching source/model hashes, APK hashes, serial, workflow settings and untampered transcripts/counts. Assertion failures, crashes and partial transcripts stop the run; no automatic retry or overall success receipt hides them. Six host tests cover these requirements. Use --classes ClothingSearchRaceTest,GarmentSummaryRaceTest for this bounded acceptance. Add --include-workflows for the separate clothing screen workflow when required.

Build/lint passed in app/build/clothing-publication-build.txt. Device outcomes belong in app/build/local-core-verification/receipt.json and its per-class transcripts; read those before claiming device completion. Earlier 76-case split acceptance remains scoped to the earlier source snapshot.

Sources/models/APKs stayed unchanged during the run. All 25 host tests passed, including six verifier tests, and build/lint passed. Per-class receipts and the overall receipt identify only this two-class selection; they are not a rerun of all earlier 76 cases.
