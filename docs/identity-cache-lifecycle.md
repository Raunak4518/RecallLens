# Face and object cache lifecycle

PL044 and PL062 now retain an encrypted fingerprint of the bounded decoded input alongside identity gallery/reference vectors. IdentityScan computes the fingerprint on the same oriented image used for detection and encoding. It uses the existing pixel_revision column, so schema 8 and the vector codec remain unchanged.

IdentityMatcher reconciliation removes inaccessible records and keeps hash-bearing records with changed source metadata private until verification. CachedIdentityScan validates the selected source and installed model revision before using an entry. A new source revision requires decoding the affected photo and checking the fingerprint through PhotoLibrary.inspectPhoto. Equal input rebinds the existing entry to the new revision without opening a detector or encoder. Cancellation is checked before writing the verified entry.

An image edit or model change takes the inference path. Legacy entries without a fingerprint cannot use metadata-change reuse. Failed access/verification cannot publish the cached payload. Entries for temporarily unavailable authorized sources follow the existing hidden-retention rule; removing their scope prunes them. A stale photo selection is rejected without removing a newer valid cache entry or opening inference.

Identity fingerprints prove equality of the input available to this particular model pipeline, rather than equality of the original file. They do not establish that an object is the user's property or that another URI contains the same person. They do not create Named confirmations, renew cloud approval, migrate garment evidence or prove original-file identity. Named confirmations use their separate full-file proof. Exact-object and face ranking still return suggestions for user confirmation.

The new IdentityCacheMetadataTest uses the bundled real face and toy-car fixtures, with an existing confirmed anchor and unconfirmed candidate/lookalikes. It populates the cache, replaces the encoder factory with one that throws if opened, renames the anchor and moves a candidate within the same volume, then verifies zero cache misses, unchanged vector bytes and unchanged ranking scores. It checks encrypted reopening, current revision binding, stale selections, subsequent edits and narrowed source scope. Existing IdentityMatchingTest continues to cover lookalike order, confirmation-only search, changed model revisions, edited images and deletion.

Hashing adds a bounded pixel pass during initial identity analysis and after a metadata revision change. Unchanged known revisions use the cached path. ARM latency, energy and large-gallery hash/index overhead remain measurement requirements; emulator cache operation counts cannot establish physical-phone speed. New-URI/cross-volume continuity remains separate work.

The five-test identity/lifecycle run passed on Android 17 x86_64 emulator-5580 in 168.480 seconds. Both face and object workflows passed the throwing-factory check, exact vector/score equality, stale-selection rejection, one inference miss after editing and pruning after narrowing source scope. Existing lookalike/model-change/deletion regressions and the real Named-source lifecycle also passed. Evidence: app/build/identity-metadata-regression.txt.

A subsequent review hardened Named references for providers without a reliable source revision. PhotoReferenceSource is the narrow source-access interface consumed by PhotoSubjects; PhotoLibrary implements it. Referenced photos without a source: revision must revalidate their original-file digest even if their decoded-pixel revision matches. A fake-source regression changes original bytes while holding the decoded revision constant and verifies removal, including read failure. This affects confirmed photos requiring validation, rather than every gallery image. The eight-test confirmation/fingerprint run passed in 91.886 seconds: app/build/identity-source-guard-regression.txt.

Debug build/lint passed in identity-metadata-build.txt and identity-source-guard-build.txt. Final ARM64 APK/AAB production builds and all ten static package checks passed in identity-source-guard-release-build.txt and release-inspection/results.json. Production signing and physical-device qualification remain separate.
