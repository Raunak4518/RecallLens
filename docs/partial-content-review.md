# Independent partial-content review

Reviewed current source on 18 November 2026 during the root's source/model/tool verification freeze. This is a read-only review; no app source, tools, models or device state were changed. Existing passing tests establish their actual cases, not broad natural-language correctness.

## Preserved invariants

Named search remains confirmed-only. Partial semantic suggestions enter only the related group, never confirmed or remembered-text groups. The semantic path filters its embedding map to the confirmed entity scope before selecting top24, avoiding loss of scoped candidates merely because unrelated gallery results ranked above them globally. Accessible URI filtering is applied again when grouping. Existing source/query publication snapshots cover changed sources, mode, Named state and lifecycle generation at the ViewModel level.

The complex personal query test restricts candidates to the intersection of the confirmed person and object. The user is told that clothing, spatial relation and location may remain unverified. Place and organization labels are intentionally excluded from this appearance scope; an ordinary place name is not proof of exact GPS proximity. The real workflow test proves a scoped result renders with the partial label and disappears when switching to Named mode. It does not prove that the image actually satisfies the requested spatial relation or that CLIP recognizes every named identity.

## Concrete gaps

1. Generic unsupported relations do not receive the same partial warning. planPhotoQuery returns immediately when searchNamed returns null. Consequently a query such as "a dog behind a car" is treated as ordinary semantic content, with no SPATIAL_RELATION requirement or partial-condition label, whereas the named-person equivalent receives both. Detect supported relation requirements independently of name resolution. Add a non-personal relation test and a UI check showing that the same limitation is explained consistently.

2. confirmedEntityScope has a bounded token guard, not a complete negation/alternative parser. Explicit not/without/except/or/neither/nor correctly prevent affirmative intersection. Other constructions such as "me instead of my car" or "my photos apart from my BMW" still collect both subject IDs and require their intersection. This may hide relevant photos. Either constrain the grammar used for automatic scope to explicit affirmative constructions or expand an explicitly documented bounded exclusion vocabulary; do not claim general negation understanding from the existing three test queries.

3. Unknown self plus a known object needs a regression. With no explicit Me/Myself enrollment but a known MyBMW label, the current plan retains SELF_IDENTITY and can restrict partial suggestions only to confirmed car photos. This does not invent a self confirmation and is acceptable if clearly labeled. Add tests asserting that the self requirement remains, that an unconfirmed car cannot enter, that a confirmed car can appear only as partial, and that Named mode stays empty.

4. Partial semantic queries always return up to the ranking cap when embeddings exist, without proving that any photo satisfies the remaining request. The UI now says possible match/some conditions unverified, which is essential. Evaluate absent-item and contrary-relation prompts explicitly. The existing workflow test uses one confirmed anchor and therefore validates wiring/labeling more strongly than ranking quality. It cannot establish top1/top5 real complex-query accuracy or justify broad "all prompts" support.

5. The current partial guidance can be long when accompanied by several per-requirement messages. The ordering is correct and honest, but repeated paragraphs above results can obscure the actual photos. After correctness validation, consider one concise summary plus expandable missing-condition detail. Preserve the distinction between confirmed identity and estimated/unverified conditions.

## Larger-gallery metric review

The corrected tools/large-gallery/report_results.py checks a complete result against the frozen manifest digest, exact query set and a complete unique ranking. It counts top5 known positives, explicit negatives and unjudged slots separately. Judged precision uses actual top5 judged slots and is withheld for positive-only questions. That is more defensible than labeling every unannotated image negative. No threshold tuning or independently reviewed held-out natural-prompt accuracy is claimed in its output.

Minor hardening remains: duplicate IDs in manifest images are silently collapsed by set construction, and reported encode/rank times are not checked for finite nonnegative values. Reject those malformed inputs rather than emitting misleading size/latency metrics. A timing median over generated category queries is descriptive performance, not a confidence-calibrated search guarantee.

The corpus preparation/finalization creates category, category-conjunction and official positive-only relationship queries. It does not annotate personal ownership, face identity, historical colleges, exact garments or nearby GPS. Those app features need their own controlled/consented relevance judgments. Group partition metadata and human-written judgments should be used before presenting a final held-out product-quality claim.
