# Android and Play release audit

Reviewed 18 November 2026 against the current app sources and official Google documentation. The current requested delivery is an on-device app tested on the emulator. A hosting account and public cloud deployment are not prerequisites for local search; existing optional cloud code remains separate. This audit is a release work plan, not Play approval or physical-device qualification.

## What the app already has

The Kotlin/Compose app has persistent encrypted local OCR, scene and identity records, user-confirmed names, suggestion review, nearby search and person/color estimates. Bundled models permit offline inference. The release build targets API 36, compiles with API 37 and supports API 30+. Its manifest requests image/gallery and original-media-location access, with selected-photo scope support; it does not request video, all-files, live GPS, microphone or contacts permissions. Internet is declared for the existing optional cloud workflow and SDK behavior.

Current release inspection verifies an ARM64 artifact, disabled backup, non-debuggable release, disabled cleartext, expected exports, native ELF alignment, zip alignment and pinned assets. These ten checks do not prove that a release is signed, behaves correctly on 16 KiB hardware, passes Play review or satisfies model quality/performance gates. Read app/build/release-inspection/results.json for the exact artifact hashes and sizes after the latest build.

## Privacy declaration boundaries

Do not advertise that the app never sends any network data merely because photos are processed locally. ML Kit documents local input/output processing alongside update and usage/performance communication. The current privacy audit observed zero app UID traffic during its measured local flows, but that finite observation does not override the SDK's documented behavior. [ML Kit terms](https://developers.google.com/ml-kit/terms)

The current cloud worker can decrypt user-approved images. A redacted copy reduces visible content but is not a proof of complete anonymization. No public server is currently required for the on-device release. If the release package retains cloud configuration, make its optional nature and destination clear and keep its Data safety/privacy disclosure consistent with the enabled capability.

## Executable release work before Play submission

1. Finish the root-controlled per-class core/workflow verification and preserve exact executed/skipped counts, source/model/APK hashes and any failed transcripts.
2. Produce a signed ARM64 release APK for local distribution and a signed AAB for later Play submission. Verify the APK's certificate and the AAB's JAR signature; record only public fingerprints and artifact hashes in the handoff.
3. Use a 16 KiB emulator/device image for compatibility testing when available. Run offline indexing, encrypted reopen, text/scene/name queries, revocation and upgrade on the release package. Emulator timings remain emulator results.
4. Generate a device-specific APK set from the AAB and estimate compressed download size. Confirm installed startup with exactly the model assets included in that release. See [bundletool](https://developer.android.com/tools/bundletool); it signs generated APKs using a supplied test/release key, whereas an AAB is not signed by apksigner.
5. Complete the model/SDK redistribution inventory: pinned hashes, source URLs, actual licenses, required notices and any weight-specific restrictions. A library's code license alone does not prove model-weight redistribution rights. The independent model audit owns this check.
6. Add a privacy-policy entry and a clear derived-data removal path or documented Android app-data reset behavior. Do not imply that removing app data deletes original gallery photos.
7. Prepare actual store screenshots, support contact, age/content declarations and a photo-permission justification aligned with library-wide search. Avoid claims of perfect identification, privacy, redaction or universal OCR.
8. Upload only through the owner's Play account when explicitly authorized. Complete account-specific testing/review requirements and inspect pre-launch reports before production rollout.

## External inputs and deferred work

The local app does not wait for public hosting. Required external inputs for Play are the owner's developer-account identity/eligibility, protected signing custody/backups, support/privacy publication details and any mandated closed-test cohort. Physical ARM battery/thermal/real-gallery measurements remain required by the project plan but cannot be claimed from emulator automation. Required later LLM/VLM evaluation is a project milestone, not a generic Play requirement.

This audit changed documents only. It did not create a signing key, install on a phone, publish a policy, upload to Play or deploy a service. Official requirements can change; recheck the linked primary pages at actual submission time.
